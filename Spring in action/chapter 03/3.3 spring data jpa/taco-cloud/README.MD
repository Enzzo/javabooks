# Заметки к этой главе:
## Пример использования Spring Data JDBC
- Удалим зависимость `spring-boot-starter-data-jdbc` и добавим `spring-boot-starter-data-jpa` <br />
- Чтобы объявить сущность JPA, класс сущности необходимо аннотировать при помощи <strong>@Entity</strong><br />
- Следует заменить зависимости для <strong>@Id</strong> с `org.springframework.data.annotation.Id` на `jakarta.persistence.Id` <br />
- Так же нам не нужна аннотация <strong>@Table</strong> и реализация интерфейса <strong>Persistable</strong>. Этот интерфейс нужен был при работе с <strong>Spring Data JDBC</strong> только чтобы определить, должен ли создаваться новый или обновляться существующий объект. <strong>JPA</strong> определяет это автоматически.
- В сущность <b>Ingredient</b> над полем <b>Type</b> следует повесить аннотацию <b>@Enumerated(EnumType.STRING)</b>;
- Мы добавили <strong>@NoArgsConstructor</strong>, так как <strong>JPA</strong> требует, чтобы сущности имели конструктор без аргументов. Мы не собираеься давать возможность использовать его извне, поэтому объявили его приватным. При этом его свойства должны быть финальными, поэтому добавляем атрибут <b>force=true</b>. Это позволит присвоить полям значения: false, 0, null. Когда добавляется аннотация <b>@NoArgsConstructor</b>, то аннотация <b>@AllArgsConstructor</b> затирается и теряет смысл. Поэтому добавим аннотацию <b>@RequiredArgsConstructor</b>, которая <b>гарантирует</b>, что мы по прежнему будем иметь конструктор со всеми обязательными аргументами, помимо приватного конструктора без аргументов.
- В <b>OrderRepository</b> добавили несколько запросов с именами, привязанными к запросу, а так же метод с произвольным именем, но аннотацией <b>@Query</b>
